# Disciplina Projeto de Software 2 90h (120Aulas)

## Módulo 1 - Revisão Sobre Levantamento de Requisitos e Metodologias Ágeis 

- O papel do Analista de Requisitos (PO)
    - Intermediar a "Comunicação" entre StalkeHolders e a Equipe de Desenvolvimento,
    Gerenciando o Backlog do Projeto

- Metodologias de Desenvolvimento de Porjetos
    - CLássica / Cascata (WaterFall)
        - Foco no Projeto
        - Uma Etapa após a outra
    - Metodologias Ágeis (Scrum, Kanbam, XP, Lena)
        - 4 Pilares:
            - Foco no Usuário
            - Entregas Rápidas (Software em Funcionamento vale mais que Documentação)
            - Mudanças são bem Vindas
            - Individuos e Interação Mais que Processos e Ferramentas

## Módulo 2 - Levantamento de Requisitos 

- O que é Requisito
    -Requisito Funcionais e Não Funcionais

    - Requisito, Regra e Restrição

- Documentação de Requisito - Como Registrar

|Campo | Conteúdo | Exemplo|
|---   |---       |---     |
|  ID  |  Código Unico | RF-001 |
| Nome | Verbo no Infinitivo + Objetivo | Cadastro de Usuários |
| Descrição | O ... Deve ser capaz de ... | O Cliente deve ser capaz de realizar seu cadastro na Plataforma |
| Prioridade | Importância para negôcio | Alt (Precisa Ter) |
| Regras Vinculadas | Referência á RNF | RNF - Banco de Dados |

## Módulo 3 - Técnicas de Levantamento de Requisitos

- Briefing:
    - Coleta de Dados Inicial do Projeto
    -Não Existe um Formato Único:
        -Relatório
        - Reunião
        - Telefonema
        - Email

-BrainStorm
    -Reunião Rápida entre uma Equipe Multidisciplinar com Objetivo de Resolver um ou mais Problemas
    - Pode acontecer de Forma Estruturada ou Não

- Questionário
    - Perguntas Direcionadas com Objetivo de Obter Informações Relevantes para Montagem do Escopo do Projeto

- Entrevistas
    -Coleta de Dados com StakeHolders (Pessoas Interessadas no Projeto)

-Etnografia
    - Ato de Observar p Dia-a-Dia dos Envolvidos no Projeto (Clinetes e Usuários)
    - Entender a Cultura de Empresa

- Workshop
    - Apresentação do Projeto em Feiras, Eventos e Workshops com Intuito de Apresentar
    informações sobre o Produto desenvolvido
    - necessário de um MVP para apresentação

- Prototipagem
    - Criação de modelos visuais para melhor identificação dos elementos do Projeto
    - Os Protótipos podem ser de baixa (Rafe), Média, Alta Fidelidade
